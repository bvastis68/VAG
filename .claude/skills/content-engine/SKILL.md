# Content Engine

Build content from real source material. One post carries one real claim.
Specificity beats adjectives. Never sound like the platform.

Defer to `firm-context` for house style. Run `brand-voice` first and reuse the
VOICE PROFILE.

## When to use

- Drafting a LinkedIn post or comment
- Scripting a short video or longer explainer
- Writing a newsletter or client letter meant for a wide audience
- Turning one asset into a sequence across channels

## Source first

Never start from a post formula. Start from a source. In order of strength:

1. A live client situation, anonymised beyond recognition
2. A real market or tax development with a date
3. A PLAUD transcript of Billy explaining something out loud
4. An existing one-pager, deck, or client letter
5. A named research piece the practice already relies on

If there is no source, there is no post. Say so instead of inventing one.

## Steps

1. Identify the anchor asset.
2. Extract three to seven atomic claims from it. One claim per output.
3. Rank claims by sharpness, novelty, and whether they can be supported.
4. Assign one claim per piece.
5. Adapt structure per channel using the rules below.
6. Run the quality gate.
7. Flag anything needing compliance review before it can be posted.

## Channel rules

### LinkedIn

Open with the claim or the tension. Expand just enough that a lawyer or an
accountant outside the niche can follow it. No journey posts. No praise
stacking. No lesson framing unless the source material genuinely is reflective.
No closing question written to farm comments.

Length: short enough that the whole post is visible without expanding, unless
the argument genuinely needs more.

### Short video

Script to the visual sequence, not the page. The first seconds show the result,
the problem, or the punch. Write for the ear. If it reads better than it sounds,
rewrite it.

### Longer video or explainer

Organise by argument, not by section headings. Show the tension early. Chapter
only when it helps.

### Newsletter

Open with the point. No warm-up paragraph. Every section adds something new.
End with a specific next step, not an invitation to reach out.

## Repurposing

One anchor, several outputs, each carrying a different claim. Never post the
same copy on two channels with the length adjusted. That is the fastest way to
look automated.

## Output format

```
CONTENT SET

Anchor: [source, with date]
Angle: [the core claim the set lives in]
Voice: [VOICE PROFILE reference]

Drafts
One block per piece: channel, the claim it carries, the draft.

Posting order
Only if sequence matters to the argument.

Compliance flags
Anything that constitutes advice, a performance claim, a forward-looking
statement, or a product reference. Named piece by piece.

Gaps
What must be verified or supplied before any of this can post.
```

## Quality gate

Before delivering, every draft must clear all of these.

- It sounds like Billy, not like LinkedIn
- It carries one real claim, with a concrete observation or proof point
- No hype language survives
- No engagement bait survives
- No copy is duplicated across channels
- Any call to action is earned and specific
- Nothing in it would work unchanged for any other advisor in Canada

## Hard bans

Delete and rewrite on sight: "In today's volatile market", "navigate
uncertainty", "unlock", "game-changer", "the 60/40 is dead" as a standalone
hook with nothing behind it, fake contrarianism, performance claims of any kind,
client anecdotes that could identify a household, and closing questions written
to bait replies.

## Rules

- No specific fund, manager, or product names in public content. Strategies stay
  generic.
- No performance figures, projections, or return claims. Ever. Not even
  historical, not even sourced.
- No client story goes out unless it is anonymised past recognition and Billy
  has confirmed it is safe to use.
- Anything that reads as advice goes to RBC DS compliance before it posts.
  Flag it. Do not decide it is fine.
- Never cite a statistic without a source and a date.
- Short sentences. Active voice. No emojis. No em dashes.
